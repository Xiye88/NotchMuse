# v0.7.1 Metadata Resolution and Consensus Report

日期：2026-09-04

## 49 条 Metadata Gap

Ground Truth v1 的 49 条 `insufficient_metadata` 对应 36 首歌曲。

| 字段 | 当前覆盖 | 已证明可解除 ambiguity | 判断 |
| --- | ---: | ---: | --- |
| source album | 49/49 | 0/49 | 只有 source 一侧，不能决策 |
| candidate album | 0/49 | 0/49 | 多个 Provider raw schema 有机会补采 |
| source/candidate ISRC | 0/49 | 0/49 | 只有 LRCMux 已证明 candidate 侧存在 |
| release year/date | 0/49 | 0/49 | Apple Music source 侧可读，candidate 侧未证实 |
| provider-native candidate ID | 0/49 | 0/49 | 当前 candidate ID 是 evidence hash，不是 native ID |
| version keyword | source 14/49、top 7/49、second 19/49 | 0/49 | 只能作冲突保护，不能充当 Ground Truth |
| lyric body / timing identity | 0/49 | 0/49 | 同 metadata 版本仍需正文或人工真值 |

因此本轮的严格答案是：**已证明可解决 `0/49`**。`49/49` 都可以进入新的 raw
metadata 重采集，但“可以采集”不等于“理论上已经解决”。

## ISRC Identity Feasibility

- Spotify AppleScript 无 ISRC；Spotify URI/ID 到 ISRC 需要 Web API、OAuth 和
  在线请求。
- Apple Music AppleScript 有本机 persistent ID，但无 ISRC/catalog ID；MusicKit
  或 catalog API 会引入 token、storefront 和网络依赖。
- LRCMux 返回 candidate ISRC；其他 Provider 没有已证明的同一映射键。
- player 有 ID、Provider 有另一套 ID，并不构成可验证 bridge。

结论：ISRC 值得在 Benchmark evidence 中采集，但当前不值得进入 Production。

## Cross-provider Consensus Offline Experiment

实验规则：同一 source track 下，规范化 title、完整 artist set、版本 marker 一致，
duration 容差 `±2s`；只有一侧得到至少两个 Provider 支持时才输出代理选择，随后
执行 version conflict guard。

| 结果 | Case |
| --- | ---: |
| version guard 后代理选择 | 6/49 |
| version guard 后 unresolved | 43/49 |
| 三 Provider 门槛下代理选择 | 0/49 |

`6/49 = 12.24%` 只是选择覆盖率，不是确认解歧率。Ground Truth 的可评估
top/second/neither 分母仍为 0，所以 ambiguity reduction、correct rate 和 confirmed
false positive 都是 `N/A`。中间支持分桶会随 artist/title 规范化方式变化，且
结果对 duration 容差敏感，因此不能作为身份真值。

结论：Cross-provider consensus 当前**无效于 Production Gate**，只能作为
Benchmark 取样优先级信号。
