# NotchMuse v0.7 Lyrics Quality Hardening Gate

日期：2026-08-31

## Final Decision

**CONDITIONAL GO**：允许继续人工标注、歌词正文核验与 Benchmark-only evaluator
修正；不批准 Production Matcher 修改。

## 1. 最新歌词质量基线

- run 50 Overall：`890/1000` (`89.0%`)。
- Top Songs：`272/300` (`90.67%`)；Top 100：`97/100` (`97.0%`)。
- 最近 7 runs Overall：`89.09%`；Top Songs：`90.52%`；Top 100：`96.29%`。
- `wrong candidate` 与 confirmed false positive 因 `0` 人工真值而不可计算。

## 2. 热门歌曲 miss 前三大原因

当前只能给“证据层”，不能给互斥根因：

1. Provider no-result：run 50 的 110 首 miss 中 108 首至少有一条 no-result 证据。
2. Matcher rejection / ambiguity：103 首有 rejection，31 首有 ambiguity 证据。
3. Provider parser/health：Soda 让 110 首全部出现 parser 证据；这是共现噪声，不能说每首都由 parser 导致。

Network 只出现在 5 首 miss 中，不是当前主要方向。

## 3. Wrong candidate 前三大原因

由于没有人工真值，不能声称已测得真实 Top 3。当前最高风险假设是：

1. Live/Remix/Remastered/translation/radio edit 等 version conflict。
2. artist set 与 feat/with 表达不完整，raw artist exact 不足以判身份。
3. 候选 album/ISRC/native ID/歌词正文缺失，使小 gap/tie 无法判定。

这些是待验证风险，不是已确认发生率。

## 4-6. 责任边界

- Provider：无候选、Soda invalid response、LRCMux 404 语义、timeout/network、低 unique contribution。
- Matcher：有候选但 below threshold、ambiguous gap、版本冲突保护与候选 dedup 决策。
- Metadata：candidate album/ISRC/native ID 缺失、artist set 不完整、版本关键词不对称。

## 7. 最值得进入下一步的 Offline Experiment

对 50 条热门 miss 与 40 条 ambiguity 样本做 strategy-blind 人工标注，并保存
候选歌词正文；标签限定 `top/second/neither/uncertain`。先修 evaluator，使 Current
baseline 包含成功与失败决定，再在独立 holdout 计算 correct/wrong/false-positive delta。

Duration 是当前区分力最高的 signal，但它只能用于分层，不能直接上线。

## 8-9. Production Gate

- 小规模 Production Matcher 修改：**不批准**。
- 当前只允许的改动：Benchmark-only 数据标签、evaluator 统计口径和 evidence schema；
  不允许改 Production score、threshold、normalization、dedup、Provider order。
- 重新申请条件：labeled holdout 显示正确选择率提升，且 confirmed false positive = `0`。

## 10. 下一平台

继续延后。优先级维持 Universal Binary / Intel > QQ Music > NetEase > YouTube Music；
只有 Universal Binary 有公开可维护路径，但仍需真实用户需求和 Intel 真机 QA。

## 下一批唯一建议

完成 `50` 条热门 miss 和 `40` 条 ambiguity 的人工真值闭环，优先试听 11 首 Timing
异常候选；在真值完成前停止增加 ranking signal。
